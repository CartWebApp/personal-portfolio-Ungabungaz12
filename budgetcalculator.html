Project Case Study: Budget Calculator

The Goal:

With the help of the students at the Center for Advanced Research and Technology’s Web Application course, I was able to develop a comprehensive budget calculator with automatic tax calculations and career selections, developed for the EECU.

The Technology Stack:

  • Languages: HTML5 and CSS3, JavaScript with Chart.JS
  • Tools: Figma for extensive user interface development options, Visual Studio Code for development and Git/GitHub for version control.
  • Deployment: Hosted via Netlify to ensure global accessibility and performance.

Concepts Learned

  • Pull Request: I furthered my knowledge of Github repositories to both develop and accept pull requests for and from my peers.
  • External Scripts: With the requirement of Chart.JS, I learned how to effectively import online scripts and implement them within my code.
  • External Databases: I learned how to pull a JSON database and present it within a dropdown, with each option tied to a monetary value for career selection.

Challenges & Solutions

    • The Problem: I wasn’t sure initially how to use Chart.JS
    • The Solution: I perused the documentation for Chart.JS, learning about how it works and how to implement it efficiently.
    • The Problem: My design required an automatically updating value to be present in the middle of the chart to show the user’s current budget, which the base Chart.JS package didn't support.
    • The Solution: I developed a custom plugin, referencing both MDN resources and Chart.JS documentation to have a ctx.text value be the final budget variable.
    • The Problem: There were a few merge conflicts when accepting certain pull requests.
    • The Solution: I learned how to peruse the changes made within the pull requests and edit them, or implement them in my code, so that the pull request would be resolved.

Habits of Mind in Action:

  • Persistence: This was one of our longest projects that we made at CART, and it required working with so many different people to develop your app, but despite this, everyone pulled through.
  • Communication: This project relied heavily on communication, as any changes made before a certain date had to be from someone that wasn’t you, requiring other people to communicate with you to develop the app and send a pull request.
